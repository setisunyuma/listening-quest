# 設計判断の記録

仕様に書かれていない細部について選んだ初期値と理由です。いずれも変更可能です。

| # | 判断 | 理由 |
|---|---|---|
| 1 | 新規リポジトリのため、仕様の推奨配置のモノレポで作成。既存の生成器リポジトリは存在しなかったので、生成器 CLI（`lq`）も同じ Python パッケージに実装 | 仕様 2・3 |
| 2 | 前作 `proseka-strength-lab/work_c2c3/app/styles.css` を**読み取りのみ**で参照し、色・パネル・折りたたみグループ・カード・虹色/紫の達成枠・下部タブの考え方を引き継いだ。前作のコード・画像・履歴は取り込んでいない | 仕様 12 |
| 3 | Python 3.13 / Node 22 LTS / Next.js 16.4 / React 19.3 / PostgreSQL 16 / FastAPI 0.121、依存は `uv.lock` と `package-lock.json`、コンテナはタグ固定 | 実装時点の安定版 |
| 4 | 内容生成・検品の既定モデルは `gpt-6.1-terra`（価格表で中位）。音声は公式の移行先 `gpt-realtime-2.1-mini`（Realtime、発話ごとのセッション）、音声認識は `gpt-transcribe`（旧 transcribe 系は 2027-02-26 終了予定のため） | 2026-11-12 の公式ドキュメント |
| 5 | Realtime の usage が返らない場合は「不明」として見積額で計上 | 価格不明を 0 にしない |
| 6 | demo と live は `realm` 列でデータ領域を分離。ユーザーはどちらか一方に属し、全クエリが realm で絞り込む。モックの確認記録は demo 以外では作れない | 仕様 20 |
| 7 | 付属の例題 24 件（5 モード、共通テスト主要 10 形式・準1級 3 Part・1級 4 Part・C1 3 形式・C2 3 形式、共有音源の複数設問・図表依存・順序・対応づけ・採点グループ・Real-Life 事前表示・同一音声の別設問版を含む）は実装者が本文・正答・根拠・誤答理由を確認し `author_reviewed` として記録。API 検品は未実施 | 仕様 16・20 |
| 8 | 本番形式の待ち時間（共通テストの読み時間・解答時間、C1/C2）はアプリ独自の初期値。英検の 10 秒は仕様の指定値 | 公式音源の実測は未実施 |
| 9 | 2026 年度の形式・解答欄・配点は仕様の値を採用し、`common_test/2026_main`・`eiken_pre1/2026_2`・`eiken_1/2026_2` として版付きで保存。**公式 PDF・原稿との逐語照合は未実施**（プロファイルの `sources[].verified` に明記） | 仕様 4 |
| 10 | 学習日の判定にはサーバー時刻を使い、端末時計は参考保存のみ | 二重計上の防止 |
| 11 | 予算日は UTC 日で区切る | API 請求の日付と揃えやすい |
| 12 | 「初見」権は user × stimulus_fingerprint で一度だけ。改版・別設問版・別モード版も同じ台本なら接触済み | 同じ本文の量産を新しい証拠にしない |
| 13 | 弱点判定の閾値は平均 70% 未満（5 観測以上） | 難度調整の 60/85% の中間。暫定 |
| 14 | 日課の 1 枠の時間上限は推定時間 × 1.25 を 30 秒単位に切り上げ | 差し替え時に長すぎる Unit を入れない |
| 15 | 実力チェックの教材は提出後に練習プールへ移し復習に使う（初見としては数えない） | 素材の再利用 |
| 16 | ラジオは Unit ごとの radio トラックを連結した「番組」ファイルを学習者の操作でサーバー側で作る。作成時点で含まれる全 Unit に解答アクセスを記録 | 細切れ再生やタイマーに依存しない／露出の追跡 |
| 17 | オフライン解答の端末保存は IndexedDB、音声は Cache Storage（ユーザー別名、サイズと SHA-256 を検証してから「保存済み」表示）。Service Worker はアプリの殻のみ | 更新で未同期回答を消さない |
| 18 | 開発時の `/api` 中継は Next.js の Route Handler（実行時に `API_INTERNAL_URL` を読む）。本番は Caddy が直接 API へ | rewrites はビルド時に固定されるため |
| 19 | 図表は構造化データからテーブルとして描画し、教材中の HTML は受け付けない（スキーマに HTML 項目が無い） | 仕様 5 |
| 20 | 誤答理由の「システム推定」は誤答した設問の第1技能タグ。本人申告と別欄 | 仕様 6 |
